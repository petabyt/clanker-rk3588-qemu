# RK3528 SD boot (experimental)

The ROCK 2A test boots a combined SD image through the unmodified rkbin DDR
v1.14 and BL31 v1.21, U-Boot SPL and U-Boot. It uses synthetic DDR controller
responses and an experimental BootROM substitute; the actual BootROM ABI is
not verified. The DDR binary reports a capacity-detection error and 512 MiB;
the shim removes its inconsistent memory tag so U-Boot uses the modeled 256 MiB.

Inputs are from rockchip-linux/rkbin commit
`3e288fe814e059dd06833495f845cab04ac20a5c`, and are not redistributed.
The build verifies their hashes and uses the checked-in U-Boot commit in a
temporary tree. Python pyelftools and the AArch64 cross toolchain are required.

```sh
make test-rk3528-sd \
  RK3528_DDR=/path/to/rk3528_ddr_1056MHz_v1.14.bin \
  RK3528_BL31=/path/to/rk3528_bl31_v1.21.elf
```

The test uses a snapshot and verifies the SD image hash remains unchanged. The
test build disables unused hardware and the eMMC device; it is not an unmodified
board image. SPL warns that it cannot map the BootROM device to an ofpath;
BL31 warns about secondary CPU state and missing optional OP-TEE. The test
interrupts autoboot: unattended bootflow scanning can access unmodeled devices.
SPI boot, real DDR training and full hardware fidelity are not tested.
